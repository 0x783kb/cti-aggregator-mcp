> 本文件是九条规则的完整判定逻辑、参数标定依据与能力边界。
> 主文件 SKILL.md 只保留规则速览表——**执行检测时才需要读这里**。

## 数据基线（2026-08 银狐基础设施测绘标定）

本 Skill 的品牌库、参数与阈值均基于 2026-08 银狐仿冒资产测绘结果校准（L1 域名级硬证据仿冒域 N=17,342）：

- **品牌口径**：按「仿冒对象」颗粒度建条目（子品牌独立，如 UU加速器/网易云音乐/有道各自成条），不把品牌系合并归组
- **域名年龄**：WHOIS 唯一注册域 11,908 中 2026 年注册 9,096（95.9%），月峰值 2,440（2026-05）→ 规则六参数 **a=2、b=6**
- **黑产供应链**（L3 辅助信号）：自建邮箱域 xxcloud.ai(988)/baituo.io(420)/ningqi.live(231)/cloudworld.club/fengyun.lol；高频注册商 北京新网(2,260)/Web Commerce(1,984)/Dominet HK(1,045)
- **TLD 特征**：L1 中 .cn 占 93.9%；异常 gTLD 长尾 .xyz(222)/.top(37)/.icu(22)/.lol(12)
- **ICP 判别力提醒**：银狐 .cn 仿冒域普遍已用真实身份完成备案，「无 ICP」在银狐场景判别力有限 → 规则三降权为 30 分
- **站群外壳模式（2026-09-01 实测标定）**：`apps-{品牌拼音}.com.cn` 批量注册外壳域——apps-aisi.com.cn（仿爱思，2026-07-28）/ apps-hupu.com.cn（仿虎扑，2026-08-15），配套中继控制域 noah-ssh.com.cn（2026-08-10，Web Commerce 注册）+ 最终分发域 ryzhe.com（2026-08-28，Dynadot，安全中心威胁标签「黑灰产/仿冒网站」）；不同域用不同注册商/邮箱/NS 隔离关联（反溯源），但命名模式与注册时段高度一致
- **中继分发（2026-09-01 实测标定）**：外壳域页面 JS 内嵌中继池——`relays.json` 分发节点列表（noah-ssh.com.cn）+ 各节点 `/api.php?t=` 动态返回 `download_link`（ryzhe.com/down88），Cloudflare Workers（*.workers.dev）作免费冗余节点；下载链接不写死在页面，静态抓取不可见
- **工具软件仿冒站群（2026-09-04 实测标定，16 域批次）**：一批 16 个银狐域暴露出**连字符命名 + 共享 NS + 子域农场**三重特征：
  - **命名前缀体系**：`app-`(app-microsoft-edge)/`cn-`(cn-drawio)/`pc-`(pc-razerzone·ocam-pc)/`zh-`(zh-diskgenius)/`gw-`(gw-sogou)/`-cn`后缀(steelseries-cn)，以及无前缀的 `{品牌}-{产品}`(baidu-pan·calibre-ebook)——**共性为连字符 .com.cn**，16 域中 9 域符合；正规中文品牌官网极少使用此类域名
  - **共享 NS 基础设施（最硬关联证据）**：`ns1/ns2.363.hk` 承载 8 域、`ns1/ns2.julydns.com` 承载 3 域。NS 复用 = 同一操作者，且比注册商信号更难迁移掩饰（注册商随时可换，自建 NS 迁移成本高）
  - **注册人身份复用**：张龙飞/759097882@qq.com 关联 4 域（calibre-ebook、kaspersky-lab.hl.cn、translate-youdao.hl.cn、zh-diskgenius）；郭兵/justindaniel9200@gmail.com 关联 2 域；梁平安/zhaojianjinsha@gmail.com 关联 2 域
  - **子域农场（新型手法）**：两字母 .cn 主域 `hl.cn` 下挂 `kaspersky-lab`/`sejda`/`translate-youdao` 三个品牌子域——注册一个主域即可无限开设品牌子域，成本更低、IOC 封堵更难覆盖
  - **注册时段高度集中**：2026-05-22 → 2026-07-12（约 7 周内 14 域）
  - **随机串域混入**：gehie246.com / iualef.net / oijfwe.net 无品牌词，属投递或 C2 节点，**规则一不适用**，需靠域龄 + 共享 NS + 注册商等 L3 信号识别（本次分别得 73/15/15 分，未达红线）

## 判定架构：三层证据（测绘方法论的单 URL 落地）

| 层级 | 规则 | 证据强度 | 判定逻辑 |
|------|------|----------|----------|
| L1 域名级（硬证据） | 规则一 | 一击定论 | 命中 + （页面下载信号 或 域龄<180天）→ 直接红色 |
| L2 页面级（组合证据） | 规则四/五/八 | 累计加分 | 与 L1 叠加抬升总分 |
| L3 关联级（辅助信号） | 规则六/七/九 | 不可单独定罪 | 域名年龄、供应链特征仅作佐证/补偿 |

## 核心检测规则

### 规则一：域名仿冒检测（60分）

采用4类匹配策略 + 去连字符二次检测：
- **规则A：精确段匹配** — 标签段完全等于品牌关键词（所有长度）
- **规则B：标签子串包含** — 关键词在任一label中出现（仅kw≥5字符）
- **规则C：关键词堆叠** — 同一关键词在所有段中精确出现≥3次（所有长度）
- **规则D：约束编辑距离** — Levenshtein≤2且长度差≤2（仅kw≥6字符）

**去连字符二次检测**：若域名含 `-` 或 `_`，去除后重新执行规则A/B/C，覆盖连字符插入+子串嵌入的复合变形（如 pay-pal-login.hl.cn）。

**去重复字母二次检测**（2026-08 测绘反哺）：若域名存在连续重复字母（如 `gmaiillli`、`baiduu`），将连续重复字符折叠为单个后重新执行规则A/B/C，覆盖字母堆叠混淆——测绘 WHOIS 实锤黑产邮箱域 `gmaiillli.com` 即靠此手法仿 gmail 且逃过编辑距离检测（`gmail` 仅 5 字符，够不到规则 D 的 kw≥6 门槛）。

### 规则二：压缩包下载检测（最高40分）

- **Phase A（主动扫描）**：扫描跨域压缩包链接，高危+10/个，中危+5/个，上限30分
- **Phase B（被动拦截）**：实际下载时检测，域名已有≥30分嫌疑+40，弱信号+10

### 规则三：ICP备案缺失检测（30分，2026-08 降权）

检测中国网站的ICP备案号，覆盖34个省级行政区简称。格式：`{省份}ICP{备|证}{6-12位数字}号`

**降权依据**：测绘显示银狐 .cn 仿冒域普遍已用真实身份完成 ICP 备案并长期存活，「无 ICP」单独不构成强判别信号；本规则改为与规则一（域名仿冒）同时触发时才有较强定罪力，单独触发为中等信号。

判定链路：
1. 官方域名 → 0分 PASS
2. 有ICP + 可点击政府链接 → 0分 PASS（已核验）
3. 有ICP + 缺政府链接 + 页面有中文 → +30分（虚假备案嫌疑）
4. 有ICP + 缺政府链接 + 页面无中文 → +15分（虚假备案嫌疑）
5. 无ICP + 豁免白名单（外国站点） → 0分 NEUTRAL
6. 无ICP + 有中文 → +30分 TRIGGERED
7. 无ICP + 无中文 + 非白名单 → +15分 WARN
8. 规则三命中 + 规则一同时命中 → 报告中标注「ICP缺失与域名仿冒叠加」，定罪力升级

### 规则四：链接分析（最高70分）

**Part A（先执行，可叠加）**：
- 同页链接≥5个+20分（完整URL完全一致）
- 死链≥1个+20分（HEAD请求验证）
- 重复链接≥4个+20分（不同元素指向同一链接）
- 若该链接为下载链接+10分（附加）

**Part B（仅当Part A为0时执行）**：
- 外链绑在下载按钮上+10分
- 外链指向压缩包格式文件+10分

### 规则五：代码工程化检测（最高60分）

**子规则A：结构信号组合判定**：
- 信号1：DOM节点数<100（页面结构过于简单）
- 信号2：无主流框架痕迹
- 信号3：外部资源去重总数<5（脚本+样式+图片+字体+媒体）
- 信号4：异常JS引用模式

组合判定：
- ≥3个信号 → +30分（高度可疑）
- 2个信号 → +20分（中度可疑）
- 0-1个信号 → 0分

**子规则B：关键词预筛选+Emoji密度检测**：
- 先通过推广关键词预筛选确认页面性质
- 计算Emoji密度：`density = (emojiCount / textLength) × 1000`
- 分段线性映射：
  - density < 2.0 → 0分
  - 2.0 ≤ density < 10.0 → `(density - 2) / 8 × 30`
  - density ≥ 10.0 → 30分（封顶）

### 规则六：域名年龄评分（最高60分）

基于RDAP协议查询域名注册日期（rdap.org），使用S型衰减函数计分：

```
score = floor(60 / (1 + (x / (60 × b))^a))
```

**参数已标定（2026-08 测绘）**：a = 2，b = 6（半衰期约 360 天）。依据：WHOIS 唯一注册域中 2026 年注册占 95.9%，仿冒域几乎全部为当年新注册，1 年以上老域显著更安全。

| 域龄 x（天） | 得分 | 语义 |
|---|---|---|
| 0–30 | 60–58 | 强可疑（当月注册） |
| 180 | 48 | 强可疑 |
| 360 | 30 | 中度可疑（半衰期） |
| 720 | 12 | 弱可疑 |
| 1095+ | 5→0 | 基本不可疑 |

x = creation_days（域名已注册天数）。新注册域名（x→0）：score→60（最高可疑）。随注册天数增加，分数逐渐衰减至0。**RDAP 查询失败 → status=neutral，不加分不减分，不要臆造年龄**。

### 规则七：域名年龄减分（最高-20分）

对于注册时间足够长的域名，通过减分抵消部分可疑分数：

| 注册天数x | 减分分值 |
|-----------|----------|
| x < 180 | 0（新域名不减分） |
| 180 ≤ x < 730 | floor(20 × (x - 180) / 550) |
| x ≥ 730 | 20（最大减分） |

**执行条件**：
1. 仅当当前可疑总分≥20时才应用（避免对低分网站过度减分）
2. **防负保护（2026-09 修复）**：减分上限同时受规则六得分约束（`deduction = min(deduction, rule6.score)`）——730 天以上时规则六仅剩约 12 分，若仍减 20 会把该维度打成负分，语义错误。老域名补偿的本意是抵消可疑分，不允许超过年龄维度自身的可疑度

### 规则八：下载链接跨域检测（最高30分）

检测下载文件链接的域名是否与当前页面跨域：

1. 同主域名 → 不加分
2. 跨域（不同主域名）→ +10分
3. 跨域 + 命中下载域名黑名单 → +20分
4. 跨域 + 黑名单 + 新注册域名 → +30分
5. **中继分发模式（2026-09 新增）**：页面 JS 含 `relays.json` 节点池 / `workers.dev` 中继节点 / `download_link` 动态下链字段 / `/api.php?t=` 时间戳下链接口 → **+15分**（不低于文件直链跨域分）。这是站群外壳实测暴露的反检测分发手法：下载链接不写死在页面，通过中继节点池动态拉取，静态抓取看不到最终地址

### 规则九：黑产供应链信号（L3 辅助，最高20分）

来自 2026-08 测绘的黑产注册供应链特征，**仅作辅助信号，不可单独定罪**：

| 信号 | 数据来源 | 分值 |
|------|----------|------|
| 域名后缀命中异常 gTLD（.xyz/.top/.icu/.lol/.sbs/.click） | L1 长尾 TLD 分布 | +5 |
| **站群外壳域模式（`{修饰词}-{品牌}.com.cn`）** | 2026-09-01 实测 apps-aisi.com.cn（仿爱思）/ apps-hupu.com.cn（仿虎扑）；2026-09-04 扩充前缀至 app-/cn-/pc-/zh-/gw-/www-/dl-/soft-/official-/client- | +5 |
| **连字符仿冒域（任意 `xxx-yyy.com.cn`）** | 2026-09-04 实测：16 域中 9 域符合（baidu-pan/calibre-ebook/cn-drawio/gw-sogou/ocam-pc/pc-razerzone/steelseries-cn/zh-diskgenius/app-microsoft-edge）；正规中文品牌官网极少使用连字符 .com.cn | +5 |
| **短主域子域农场（`{品牌}.{2字母}.cn`）** | 2026-09-04 实测：两字母主域 hl.cn 下挂 kaspersky-lab / sejda / translate-youdao 三个品牌子域 | +5 |
| **站群共享 NS（363.hk / julydns.com）** | 2026-09-04 实测：363.hk 承载 8 域、julydns.com 承载 3 域；NS 复用=同一操作者，需外部 WHOIS 传入 `nameServers` | +5 |
| 注册商命中高频黑产注册商（北京新网/Web Commerce/Dominet HK/Gname） | WHOIS 统计 + 2026-09 实测（deepseek-en.com，安全中心威胁标签：远控木马/银狐组织） | +5 |
| WHOIS 注册邮箱域命中黑产自建邮箱域（xxcloud.ai/baituo.io/ningqi.live/cloudworld.club/fengyun.lol/gmaiillli.com/vervetech.cc） | WHOIS 统计 + 2026-09 实测（apps-aisi.com.cn 编号邮箱 ind-350@vervetech.cc） | +10 |

注册商/TLD 是行业共性弱信号（正常站点也用新网、也用 .xyz），单独命中时报告中必须注明「辅助信号」；邮箱域命中（尤其 gmaiillli.com 这类仿 gmail 混淆域）是最强供应链证据。

**信号强度排序（2026-09-04 更新）**：注册邮箱域复用 > 站群共享 NS > 注册人身份复用 > 连字符/外壳命名模式 > 注册商 > 异常 TLD。
前三项属「同一操作者」级证据——注册商、前缀、TLD 都可随时更换掩饰，但 NS 基础设施与注册人身份迁移成本显著更高。

**共享 NS 的取数方式**：`evaluate()` 的 `domainAge` 参数支持传入 `nameServers` 数组（WHOIS 的 Name Server 字段），需调用方先做 WHOIS 查询：

```javascript
const age = {
  creationDays: 58,
  registrationDate: '2026-07-08',
  registrar: '北京新网数码信息技术有限公司',
  nameServers: ['ns1.363.hk', 'ns2.363.hk'],   // ← 传入后规则九检查站群共享 NS
};
```

## 风险等级判定（2026-09 校准）

**三层判定架构**（先走 L1 硬证据短路，再走总分）：

1. **红色（危险）——L1 短路**：规则一命中（域名仿冒硬证据）且满足任一：
   - 页面存在下载信号（规则四/五/八任一 >0）
   - 域龄 < 180 天（规则六 ≥ 45 分）
   - 总分 ≥ 100
2. **红色（危险）——总分**：总分 ≥ 100
3. **黄色（警告）**：60 ≤ 总分 < 100
4. **绿色（安全）**：总分 < 60 且无 L1 硬证据

理论满分 = 规则一60 + 规则三30 + 规则四70 + 规则五60 + 规则六60 + 规则八30 + 规则九20 = 330（规则七为负分补偿）。

## 执行流程

```
用户输入URL → 获取页面内容 → 执行检测规则 → 计算总分 → 输出报告
```

检测顺序：
1. 规则一（域名仿冒）→ 规则三（ICP备案）
2. 若规则一 PASS 且规则三 PASS/NEUTRAL（官方域或豁免域），跳过规则四~九（官方网站早期退出）
3. 否则执行规则四（链接分析）→ 规则五（代码工程化）→ 规则八（跨域下载）
4. RDAP 查询域名年龄（规则六）→ 规则七（老域名补偿）→ 规则九（供应链信号）
5. 汇总分数；若命中 L1 硬证据短路条件，直接判红色，否则按总分阈值判定
